# 功能验收结果

本版按 PDF 的 8 个核心阶段重做为实际 HTML 组件和状态驱动交互。以下结果来自云环境中 Python 静态服务器与 Chromium / Playwright 的实际运行，未把未执行的真实服务接入描述成通过。

## 1. 完整正常课程与 AI 补强闭环：通过

使用界面按钮从课程首页开始，完成：详情 → 欢迎自动进入 → 路径 → 听绘本 → 学单词 → 读绘本 → 练绘本。每个模块均经过错误汇总、需要时的补练、深度引导及模块报告；最终进入整次报告、明日计划和结束状态。

同一流程中故意制造 clean 词义错误、not 理解错误，验证：

- 下一学习环节保持锁定，前一步完成后才解锁。
- 主动问答读取当前知识点，解释 clean；普通闲聊回到课程；三轮后收束并保留原学习进度。
- 听绘本分页与高亮播放；词卡释义与词义选择；绘本跟读；图片/句子习题均实际执行。
- 本轮答错结果生成复习清单。clean 独立补练通过，转为已掌握；not 连续失败两次，进入跟读后仍为待巩固。
- 三次无关主题回答收束为示范跟读，不无限聊天。
- 后续模块独立通过 not / wash hands 后，整次报告移除已经解决的弱项。
- 最终完成 4/4 模块，7 个知识点独立通过，20 次模拟孩子开口，3 项原弱项得到补强。数字由这一条具体测试路线产生，并非写死。
- 当前运行生成并捕获 5 份自动下载报告（4 个模块 + 1 个整次）。读取本次下载文件，确认包含本地功能演示标记及具体学习记录。
- 家长中心出现对应 5 份报告；结束后麦克风禁用；重置只清空当前进度，保留已保存报告；再次进入使用相应欢迎话术。
- 此完整流程未出现 JavaScript 页面错误。

## 2. 失败与边界的针对性检查：通过

另一组界面检查故意在跟读中漏掉 not，并在补练中连续失败，确认反馈指出具体问题，跟读降级没有假装独立掌握。

- 中文弱相关回答“吃饭”被引导回洗手；相关回答继续到 wash hands；表达验证通过才更新掌握。
- 为独立检查整次计划合并，该测试使用完成模块元数据夹具，保留上述实际失败证据；最终明日计划包含 not 和完整否定句。该夹具检查不作为“四模块完整执行”的证据；四模块的执行由第 1 组完成。
- 课程内问题、课程相关拓展、普通闲聊、不适合当前儿童课程的内容有对应边界分支。
- 关闭并重新打开问答面板仍保持三轮上限；进入下一任务后才重置。
- 示例称呼与自由输入以文字展示，不插入用户提供的 HTML。
- 此组检查未出现 JavaScript 页面错误。

## 3. 提示、版式与尺寸检查：通过

- “我还没想好”只提供提示，不新增错误，也不消耗一次补练尝试。
- 逐页检查课程、复习、深度引导、模块总结、整次总结和道别画面；修正了表达卡片与主按钮的重叠。
- 1024 × 768 视口中，完整横屏画布位于可见区域，主按钮与麦克风不重叠。
- 2340 × 1080 视口实际进入全屏，画布尺寸匹配目标，讲解控制条隐藏。
- 此组检查未出现 JavaScript 页面错误。

## 验证范围

实际验证的是浏览器中的产品交互、学习状态、界面分支、文件下载、当前浏览器家长报告和全屏适配。浏览器 TTS 能力依赖运行设备；真实 ASR、LLM、RAG、发音评测及远程家长端接口尚未连接。评分、识别与“开口”事件均明确为演示规则或模拟输入。
