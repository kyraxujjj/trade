# 校验说明

版本：1.0.0。日期：2026-10-15。

## 已执行的结构检查

- 主 Skill 的 YAML 头部可解析，名称与目录名一致，包含触发用途说明。
- 主 Skill 引用的参考、模板与示例文件均存在。
- 16 套原型复用逻辑编号完整。
- 三份独立规格示例没有遗留模板占位符，规则、数据契约、来源和待决引用没有悬空编号；另有一份与原型完整规格配套的旁注视图。
- Markdown 表格列数一致，验收编号在各示例内没有重复。
- 原型实例：16 条规则，29 个验收用例；每条规则至少关联一个用例。
- 最少输入学习实例：11 条规则，10 个验收用例；每条规则至少关联一个用例。
- 轻量收藏实例：6 条规则，6 个验收用例；每条规则至少关联一个用例。

## 已完成的内容走查

- 原型中的任务、学习进度、订阅和分享使用独立状态，不把创建任务误写成全员完成。
- 任务唯一范围、角色权限、平台回执与跨系统关联明确保留待决项，不把建议写成既有能力。
- 零未完成、未知进度、没有专题三个情况分开；删除任务不重置学习事实。
- 外部分享没有可靠回执时不承诺送达，也不设置无法离开的死路。
- 学习实例没有硬套班级、分享和自动通知；收藏实例采用更短的规则与验收结构。
- 新需求可以从少量输入先得到可评审规格，不要求使用者先填写完整 PRD。

## 验证边界

这次是技能包的文件检查与规格逻辑走查，不是对产品系统的集成测试。未调用现有业务 API，未验证微信 SDK、通知送达、真实数据库权限或跨系统身份数据。

三份独立规格与原型旁注是本次按 Skill 方法撰写和检查的应用示例，没有运行独立模型的批量评测，不能据此承诺任意需求都能一次生成无缺口的最终规格。

仍有 P0 时，输出应保持“可评审”；已有明确证据与定案后，才能将相应范围标为可开发。这个边界也写进了主 Skill。
