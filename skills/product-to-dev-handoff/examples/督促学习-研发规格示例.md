# 督促学习｜把原型整理成研发规格的完整示例

> 本文示范如何应用 Skill，不代表已访问现有系统或确认接口能力。来源为本次提供的两张原型图。接口名称、字段与推荐补全均为逻辑建议。
>
> **成熟度：可评审。** 页面结构、字段及常规交互可先评审；唯一性范围、发布/删除权限、分享回执与身份关联存在 P0，相关实现须先确认。不能把这些建议当成已批准需求。

## 2. 业务目标、角色与对象

**目标**：关联教师能定位尚未完成专题学习的班级，基于专题创建一次有效督促任务，并继续查看未完成成员和发起后续提醒。

**主路径**：班级专题列表 → 发布表单 → 校验/订阅请求 → 创建任务 → 成功页 → 可选发起分享 → 列表“查看详情” → 未完成名单。

**次路径**：详情删除任务 → 权威状态更新 → 若专题仍有未完成人员，列表恢复“去督促” → 可重新创建。

| 对象 | 建议标识/关系 | 权威来源 |
| --- | --- | --- |
| 源专题 | `topic_ref = {source_system, topic_id}`；提供原始标题、内容与活动时间 | 专题来源服务 |
| 班级 | `class_ref = {source_system, class_id}`；ID 若只在校内唯一，还需学校作用域 | 各来源系统 |
| 督促任务 | `task_id`；关联源专题、接收班级、创建人和本次内容快照 | 任务服务 |
| 学生与班级成员 | 稳定学生标识 + 班级关系；不以姓名作为唯一键 | 成员关系服务/来源系统 |
| 学习完成记录 | 指定成员对指定专题的完成事实 | 学习进度权威服务 |
| 跨系统映射 | 来源系统实体与目标实体之间可验证的关联 | 关系服务；需明确归属 |

**【建议】权限**：教师仅对其仍有关联且具备操作权限的班级发布/删除。家委的可见和操作权限、任一教师能否删除他人任务，见 Q02，不能从“同班都看到详情”推导所有人均可删除。

**【建议】内容复制规则**：发布表单编辑的是任务副本，不回写源专题，也不影响其他班级任务。

## 4. 页面与关键规则

### P01｜督促学习列表

**初始读取**：通过 D01 获取当前用户的关联班级、进行中专题、权威未完成人数及有效任务引用。班级总数必须来自总量语义，不用当前页渲染数代替。

| 组件 | 展示与事件 | 规则 |
| --- | --- | --- |
| P01.C01 关联班级数 | 显示权威关联班级总数 | R-001 |
| P01.C02 班级分组 | 保留各来源班级独立分组 | R-002 |
| P01.C03 专题内容区 | 标题最多两行显示省略号；除操作按钮外，点击专题内容区不跳转；完整文本仍保存在数据中 | R-003 |
| P01.C04 未完成数 | 数值为零才触发隐藏；未知显示“进度暂不可用”，提供重试 | R-004 |
| P01.C05 操作按钮 | 无有效任务时“去督促”；有有效任务时“查看详情” | R-005、R-010 |
| P01.C06 班级完成提示 | 只有已确认存在相关进行中专题且全部未完成数为零时显示 | R-006 |

- **R-001【已明确 S01；建议补全】** 统计范围为当前用户的有效关联班级；总数不随列表分页变化。关系失效后在下一次权威读取时更新。
- **R-002【已明确 S02、S11】** 两系统班级不合并。相同名称也不能据此合并；来源标识随跳转保留。
- **R-003【已明确 S02】** 省略仅影响展示，不改变源标题和表单带入值；专题内容区本身不下钻，操作按钮单独处理。
- **R-004【已明确 S03；建议补全】** `unfinished_count = 0` 隐藏该专题；`null/未返回/读取失败`不是零，不进入完成态。统计分母与名单范围保持一致，不用本地已关联的一部分学生代替源专题应学名单。
- **R-005【已明确 S04、S08】** 点“去督促”进入 P02，携带专题及班级稳定引用；点“查看详情”进入 P04，携带有效任务引用并指定未完成 Tab。
- **R-006【已明确 S03；建议补全】** “全部完成”“无进行中专题”“进度未知”分别展示，不能互相替代。无关联班级显示关联入口或说明，具体入口取现有能力。

**刷新规则【建议】**：首次进入、从 P02/P04 返回、页面恢复到前台时重取受影响班级的任务与进度。若需要不离开页面也即时同步，另定推送/轮询约定；本例不假定已经存在。

### P02｜发布安全教育

| 字段 | 类型与来源 | 约束与校验 | 保存方式 |
| --- | --- | --- | --- |
| 标题 `title` | 文本；默认源专题名称 | 【已明确 S05】必填、可编辑、最多 40 字 | 任务快照 |
| 内容 `content` | 文本；默认源专题活动信息 | 【已明确 S05】必填、可编辑、最多 400 字 | 任务快照 |
| 附件 `attachments` | 上传组件返回的文件引用集合 | 【已明确 S05】非必填；其他限制取复用契约 | 任务文件引用 |
| 接收班级 `class_ref` | 进入页携带的班级引用 | 【已明确 S05】只展示这一项，自动选中不可取消；服务端重新鉴权 | 任务接收范围 |
| 截止 `deadline_at` | 含时区时间；默认源专题截止 | 【已明确 S06】可编辑；【建议】提交时必须晚于服务端当前时间 | 服务端保存 |
| 提醒 `remind_at` | 含时区时间；默认截止日前三天的 20:00 | 【已明确 S06】可编辑，不早于发布、不晚于截止 | 服务端保存/调度 |
| 来源 `topic_ref` | 进入页携带的源专题引用 | 【建议】不展示为可编辑文本，提交时验证来源仍有效 | 关联信息 |
| 提交标识 `request_id` | 客户端生成的本次提交稳定标识 | 【建议】网络重试沿用；主动重新发布使用新值 | 幂等关联 |

- **R-007【已明确 S05；建议补全】** 必填文本去掉首尾空白后不能为空。字符计数建议使用 Unicode 码点，空格与换行也计数，前后端同口径；该口径属于本例建议，不是“40 字”天然包含的定义。
- **R-008【建议】** 自动带入超限内容时提示用户编辑，不静默丢弃来源文字。输入期间展示长度，提交前和服务端复核。错误文案对应字段，例如“请输入标题”“标题不能超过 40 字”“内容不能超过 400 字”。
- **R-009【已明确 S06；建议补全】** 本例建议按班级所在业务时区计算日历日期；若统一采用中国时间，约定为 `Asia/Shanghai`。提醒有效区间按原型文字为 `发布时刻 ≤ 提醒时刻 ≤ 截止时刻`。时间精度和截止同刻如何执行见 Q05。

默认提醒已在过去、源截止缺失或已经失效时，展示相应字段错误，要求选择合法值；不能为了让表单可提交而静默延长截止。

修改截止后，不自动覆盖用户已经手动设置的提醒；可展示“按新截止时间重新计算”的明确动作。这是避免覆盖用户输入的建议，须在评审中约定。

**提交步骤【建议方案】**：

1. 校验来源上下文、字段和时间；未通过不发起任务创建。
2. 按平台手势约束发起订阅请求，记录允许/拒绝/取消/系统失败，不把拒绝等同于发布失败。
3. 提交 D02，由服务端重新校验权限、源对象、唯一性及当前时间。客户端显示提交中，阻止重复点击，但服务端仍需幂等保障。
4. 仅收到权威创建成功/已存在任务结果后进入 P03。结果未知时保留输入和同一 `request_id`，先查询或按幂等契约重试。
5. 订阅未获允许时，任务仍可存在；成功页说明自动通知能力受限，保留手动分享入口。此为建议，需确认 Q03。

### P03｜发布成功与下一步

- 第一步成功只表示任务服务已确认有效任务存在，并持有 `task_id`。
- 第二步用于发起外部分享，不改变学习完成记录。
- **R-011【已明确 S09；待决 Q03】** 原型要求“转发完成后显示返回首页”。能否执行，取决于外部平台是否提供足够可靠的回执。
- **【建议方案】** 无法可靠确认送达时，第二步使用“已发起分享/无法确认结果”语义；保留“返回列表”和“稍后分享”的出口，不把关闭分享面板记为已送达。
- 指定图文广告位独立加载，点击进入素材指定页面；广告缺失或失败不回退已成功任务，不阻塞返回。不得把广告类型当成任务数据的一部分。

### P04｜任务详情与未完成名单

- 通过 D03 校验当前用户权限后读取任务及关联专题进度；默认打开未完成 Tab。
- 已完成/未完成数来自同一统计口径，不以当前分页行数作为总量。
- 删除入口是否展示由任务权限决定，不由按钮文案决定。
- **R-012【已明确 S10；建议补全】** 删除成功后取消该任务尚未执行的提醒，并让列表重新读取权威状态。若源专题仍有未完成成员，则恢复“去督促”；若成员已经全部完成，专题仍按 R-004 隐藏，不能因删除而重新制造未完成状态。
- 删除不抹除权威学习事实。历史任务链接显示“任务已删除/不可用”，不得跳到另一条后来重建的任务而不说明。

## 5. 状态维度与转移

以下名称只是建议逻辑枚举，现有系统可映射到自己的状态码。

| 维度 | 状态 | 判定依据 |
| --- | --- | --- |
| 有效任务 | 无有效任务 / 已创建 / 已删除 | 任务服务事实 |
| 本次请求 | 未提交 / 提交中 / 明确成功 / 明确失败 / 结果未知 | 客户端请求及服务端确认 |
| 学习进度 | 未知 / 部分未完成 / 全部完成 | 专题成员进度，不由任务创建改变 |
| 订阅授权 | 未请求 / 允许 / 拒绝或取消 / 平台失败 | 平台实际返回；不等于消息送达 |
| 分享 | 未发起 / 已发起 / 已确认 / 无法确认 | 必须与平台能提供的证据匹配 |
| 身份关联 | 未关联 / 已验证关联 / 待核对 / 来源读取失败 | 关联服务及来源数据 |

| 转移 | 前置条件与事件 | 结果 | 异常处理 |
| --- | --- | --- | --- |
| ST01 | 无有效任务，点击去督促 | P02 初始化，尚未创建任务 | 来源失效/无权限时留在合法入口并说明 |
| ST02 | 字段合法，点击发布 | 请求提交中；服务端尝试创建有效任务 | 无效字段保留输入；不发起创建或不写入 |
| ST03 | 创建已确认 | 服务端给出任务 ID；P03 第一步成功；列表派生查看详情 | 超时但结果未知时不先认定失败，不改键盲重试 |
| ST04 | 另一操作者已抢先创建 | 本次不再创建副本，定位已有有效任务 | 若无权看该任务，返回明确权限结果 |
| ST05 | 发起分享 | 只改变分享维度 | 无回执则保持未知/已发起，不改变学习进度 |
| ST06 | 授权删除者删除有效任务 | 该任务失效、待发提醒取消；符合条件时允许重建 | 删除失败不先把所有客户端都显示成无任务 |
| ST07 | 成员完成专题 | 权威未完成数变更，重新筛选列表 | 读取失败保持未知，不用零兜底 |

### R-010｜唯一性与同步

**【建议，依赖 Q01】** 对同一“来源班级 + 源专题”只允许一条有效任务；必要时带学校/租户作用域。服务端通过等效的唯一性和幂等机制保障，技术实现不限定。

同一次提交的重试返回同一逻辑结果；不同教师同时提交，最终只能产生一条有效任务。删除后可创建新的任务代次，不复用旧任务 ID 冒充新任务。

成功后相关角色下一次读取列表看到同一结果。若产品另要求立即推送到当前停留页面，必须补充具体一致性时限与能力，不能把“同步”留作口号。

### R-013｜提醒生命周期

**【建议】** 创建有效任务后，在取得必要授权且时间有效时调度提醒。调度记录关联任务 ID/有效版本；任务删除、提醒修改时，取消或使旧版本失效。

执行前重新检查任务未删除、任务版本仍有效、提醒时间条件满足，并读取实际仍未完成的接收对象。全员完成则不发送。平台受理、送达、已读分别记录，只展示可确认的层级。

## 6. 两个系统的班级和身份关联

### 先保留原型中的差异

- 班级不跨系统合并；使用哪一方的班级必须有明确 `source_system`。
- 新建或复用班级的行为依赖来源，不能只看班级名称。
- “名单是否携带 userId”在原图已标待讨论，不能直接进入确定字段表。
- 同名后加数字的规则，仍需确认是展示别名还是会修改权威姓名；建议只影响展示，不修改真实学生标识。

### R-016｜创建、复用与加入班级

| 来源/身份情况 | 规则或待决点 |
| --- | --- |
| 已存在的云班级 | 【已明确 S11】复用已有班级，不因发布同一任务再造一个班级 |
| 授课身份发起操作 | 【已明确 S11】不能在这个入口创建班级；前端不提供该动作，服务端也复核创建权限 |
| 名单加入路径 | 【已明确 S11】按原型所指来源的名单进入规则处理，不额外增加任意加入渠道 |
| 来源班级尚无目标映射 | 【待决 Q07】明确需要在哪个系统创建什么班级、由谁触发、采用何种班级标识；不能仅凭“根据来源处理”猜实现 |
| 班级创建/映射已成功，后续任务创建失败 | 【建议】分开保存结果；重试先复用已创建的班级/映射，不重复造班级，也不自动删除已存在的班级 |

班级创建/关联状态和任务发布状态分别管理，不能用任务提交失败推断班级创建也未发生。

### R-014｜建议的关联判定

| 输入情况 | 建议处理 |
| --- | --- |
| 已有经过验证、仍有效的稳定学生映射 | 校验当前班级关系后复用映射 |
| 候选唯一，且满足已约定的学生及班级身份验证条件 | 建立具体学生—班级关系映射，并记录依据 |
| 姓名不一致但仅班级相同 | 不自动放宽成已绑定；进入核对，原型宽松匹配方案待决 |
| 同一监护人存在多个候选学生 | 不选第一条；展示有权限核对的候选或转有权人员处理 |
| 没有当前班级候选 | 显示“尚未关联该班级学生”，提供合法关联/核对入口 |
| 来源接口失败 | 显示“暂时无法核对”，可重试，不标记为身份错误 |
| 双胞胎/多个监护人交叉关联 | 按具体学生稳定标识校验，不能仅凭监护人账号或班级自动合并 |

unionId 有平台作用域，不是学生 ID，也不天然等于两个系统已经可互认的身份。请求只返回操作者有权核对的数据，不能为了解决匹配而把无关学生名单开放给任意用户。

### R-015｜解绑

**【已明确 S12；建议补全】** 退出班级后，使目标班级下相应的关联关系失效。具体是用户—班级、监护人—学生—班级还是跨系统映射，必须确认 Q04；不得默认删除其他班级、其他孩子或其他监护人的有效关系。

## 7. 逻辑数据契约

这些动作不代表已经存在的 API，更不指定数据库实现。

| 契约 | 请求语义 | 必要响应语义 | 失败/一致性要求 |
| --- | --- | --- | --- |
| D01 读督促列表 | 当前操作者上下文、关联班级范围、分页条件 | 总班级数、班级来源引用、隐藏前的进行中专题总量、专题引用/标题/截止、未完成数或未知、有效任务 ID | 权限由服务端判断；计数不拿分页长度代替；必须能区分无专题与全部被零未完成规则隐藏；允许按受影响班级重取 |
| D02 创建任务 | 专题引用、班级引用、标题/内容快照、附件引用、截止、提醒、稳定请求 ID | 新建/已存在结果、任务 ID、权威任务状态 | 字段错误、来源失效、权限不足、有效任务冲突、结果未知分别处理；服务端幂等 |
| D03 读详情/成员进度 | 任务 ID、成员筛选、分页 | 任务事实、完成统计及范围、成员记录、操作权限 | 删除/失效、无权限、来源进度暂不可用分别反馈 |
| D04 删除任务 | 任务 ID、版本或等效并发条件 | 删除结果、受影响资源范围 | 权限复核；取消旧提醒；再次创建不被旧有效任务占用阻塞 |
| D05 核对关联 | 带来源的用户/学生/班级引用及已允许使用的验证条件 | 唯一有效映射/未找到/多候选/关系冲突/来源失败 | 不能返回任意可见名单；歧义不自动绑定；记录核对依据 |
| D06 创建/复用班级关联 | 按 Q07 定案后的来源班级引用、当前身份与稳定操作标识 | 已有或新建的合法班级/映射引用 | 授课身份不能越权创建；重试不得重复造班级；与任务创建的结果分开确认 |

## 10. 这份示例真正补上的东西

原型提供了页面、主要文案和部分操作规则；本规格进一步补齐对象作用域、状态维度、权威数据、重试幂等、时间失效、平台未知结果、关系歧义、删除反向流程和可判定验收。
