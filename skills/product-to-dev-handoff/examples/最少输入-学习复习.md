# 最少输入示例｜学习总结、错题复习与不限量重练

本例展示换一个需求后，如何选择适用规则，而不是复制“督促发布任务”的全部业务。

## 用户只有这段输入

> 我想做一个学习页面：学完后 AI 总结，展示错题，可以复习和再学一次，不限制每天学多少。

## 应生成的规格示例

### 1. 目标与范围

**目标**：学习者完成一轮学习后，基于真实答题记录了解本轮结果，进入对应错题补练，或立即开始新一轮学习。

**成熟度**：可评审。以下对象和契约为建议；接入真实评测前须确认 Q01 的判定来源。没有该信息，也可先实现页面、记录模型及展示流程。

**本次包含**：本轮总结、真实错题列表、同题补练、重练入口、返回恢复和生成失败降级。

**本次不包含**：自动发布通知、跨系统学生匹配、任务分享、班级创建。新需求没有这些要求，不能从原案例继承。

### 2. 对象与语义【建议】

- `course_ref`：课程及内容版本的稳定引用。
- `attempt_id`：一次独立学习轮次；重练生成新值，网络重试不生成新轮次。
- `question_ref`：与课程版本对应的题目引用。
- `result_id`：一次实际作答的判定记录，包含答案、判定与时间。
- `review_result`：对原错题的后续补练记录，关联原 `result_id`，不覆盖首次答案。
- `summary`：某一轮记录的统计与解释文字；不是一天的学习配额。

“原错题”“补练已通过”“当前仍待巩固”分开统计。AI 总结不能把原错误记录删掉，也不能把本轮没有发生的回答写进去。

### 3. 流程与页面

主路径：学习地图 → 学习与作答 → 记录齐备 → 本轮总结 → 错题补练或选择其他内容。

重练路径：总结/地图点击再学一次 → 生成新 `attempt_id` → 从新一轮首个任务开始。原报告仍可查看，不将旧答案填成新答案。

| 页面/组件 | 明确行为 |
| --- | --- |
| P01 学习地图 | 展示内容及已有进度；已学内容仍可点击，提供查看结果与再学一次；没有每日用量阻断 |
| P02 学习与作答 | 每次提交关联当前轮次和题目；未取得判定时展示处理中，不能提前生成“错题”或“全对”结论 |
| P03.C01 本轮统计 | 显示本轮实际题数、首次正确数、原错题数；数据未知时不填零 |
| P03.C02 AI 说明 | 仅解释真实统计与困难项；不把模型的措辞当作答题判定来源 |
| P03.C03 错题入口 | 有实际原错题时展示；无错题显示“本轮检查全部通过”，不预置演示错题 |
| P03.C04 继续/重练 | 可选其他内容或立即重练；不强制等到次日、不必须先休息 |
| P04 错题补练 | 使用原题目引用或事先约定的同知识点任务，保存独立补练结果；引用不清楚时不能宣称已解决原难点 |

### 4. 规则

- **R-001【建议】** 总结的统计边界为当前 `attempt_id`。如果以后增加日统计，另按当天记录汇总，不把“本轮完成”解释成“当天不能继续”。
- **R-002【建议】** 作答正确与否来自评测契约。AI 说明只使用已有的判定结果；记录缺失时显示待处理，不自行推测。
- **R-003【建议】** 学习轮次为“进行中 / 判定等待中 / 可总结 / 已总结”，AI 文案为“未生成 / 生成中 / 成功 / 失败”。文案失败不抹去已经确认的成绩。
- **R-004【建议】** 原错题列表按真实首次判定生成。补练通过只更新该难点的当前处理状态，原答案与原判定保留。
- **R-005【建议】** 点击重练创建独立新轮次。新轮次不继承上轮答案或开口次数，但可继续读取同一课程内容。历史累计的“掌握”如何更新属于 Q02，不在本轮统计中暗定。
- **R-006【建议】** 返回与刷新恢复同一轮次、题目及已确认结果；客户端不得因刷新创建新轮次。
- **R-007【建议】** 生成 AI 文案失败时保留基本统计与错题入口，提示“总结说明暂未生成，可稍后重试”；不能编造一段已学会全部内容的鼓励语。
- **R-008【建议】** 同一创建轮次/提交作答的网络重试使用同一逻辑请求标识；用户主动重练才使用新标识，区分重试与新业务动作。
- **R-009【建议】** 只有本学习者有权查看和写入对应记录；家长或教师查看能力如需加入，单独定义关系权限，不因本例默认存在。
- **R-010【建议】** 如果统计开口次数，必须先定义事件。可采用“学习者有输入并进入一次评测处理”的口径，未识别清楚也可算一次；老师播报、示范、纯按钮点击及无输入不算。统计口径须前后端一致，不使用点击麦克风次数替代。
- **R-011【建议】** 旧版本如有“今日已结束”阻断，取消限制时同时迁移该业务状态与缓存；不能只隐藏一句结束文案，却继续禁用学习入口。

### 5. 逻辑数据契约

| 契约 | 语义 |
| --- | --- |
| D01 获取/创建本轮 | 按本人、课程与请求标识恢复或创建学习轮次，返回轮次 ID、进度、可执行动作 |
| D02 提交与判定 | 输入轮次、题目引用、实际答案和请求标识；返回可追踪判定或处理中状态 |
| D03 读取总结 | 返回本轮权威统计、原错误引用、补练状态及 AI 文案状态；不以模型生成文字代替结构化事实 |
| D04 保存补练 | 关联原判定/题目，返回独立补练记录，不覆盖首次作答 |

契约名称为建议，不表示已经有四个真实接口。研发可以用现有服务组合实现，只要业务语义一致。

### 6. 验收

| 用例 | 规则 | 给定—当—则 |
| --- | --- | --- |
| AC-001 | R-001、R-004 | 给定本轮有 7 次首次判定、其中 2 次错误；打开总结；展示 7/5/2，对应两条实际错题引用 |
| AC-002 | R-002 | 给定还有判定未返回；进入结果区；展示等待/部分已确认信息，不把缺失结果写成正确 |
| AC-003 | R-004 | 给定两条原错题，其中一条补练通过；刷新总结；原错题 2、已解决 1、待巩固 1，首次答案仍可追踪 |
| AC-004 | R-005、R-008 | 给定一轮已完成；连续主动发起两轮重练；每轮有独立 ID，之前报告保留，没有每日配额阻断 |
| AC-005 | R-006 | 给定一轮做完部分题目；刷新；恢复原 ID 和已确认答案，不创建新轮或丢失记录 |
| AC-006 | R-003、R-007 | 给定成绩已确认但 AI 服务失败；打开总结；本轮保留已总结/可总结的成绩事实，文案单独失败，基本统计和错题可用，文案可重试，无虚构成绩 |
| AC-007 | R-008 | 给定作答请求已写入但响应超时；同标识重试；不会把一次回答计成两次 |
| AC-008 | R-010 | 给定老师播报两次、学习者实际输入一次；统计开口；按约定只增加一次学习者输入事件 |
| AC-009 | R-011 | 给定旧草稿带“今日已结束”；升级后打开；仍可继续或重练，旧报告不被删除 |
| AC-010 | R-009 | 给定学习者 A 无权访问 B 的记录；使用 B 的轮次引用读取或提交；服务端拒绝，不泄露 B 的答案，也不改写其记录 |

### 7. 未决项

| 问题 | 级别 | 推荐处理 |
| --- | --- | --- |
| Q01 哪个服务/规则负责正确性判定，如何知道本轮任务齐备 | P0，影响真实评测接入 | 接入课程已有题目与评测契约；若需新建评测，先确定题型、标准答案/评分模型及判定状态，不让总结模型自行猜测 |
| Q02 跨轮次、跨日期的长期掌握与日统计口径 | P1；若首版要展示这些指标则需先定案 | 首版只显示本轮事实；长期指标另定义来源与更新规则，不能拿最近一轮全量替代历史 |

本例没有擅自增加定时提醒、订阅权限、班级分享或学生匹配。它复用了闭环、对象、状态、来源、幂等和验收思路，按本需求的实际复杂度裁剪。
