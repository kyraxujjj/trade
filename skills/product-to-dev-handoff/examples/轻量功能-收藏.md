# 轻量功能示例｜收藏与取消收藏

**输入**：文章详情页增加收藏/取消收藏，个人中心能查看收藏列表。

**输出范围**：详情按钮、个人收藏列表和关联状态；不增加班级、通知、定时任务、分享或身份匹配。

**成熟度**：可评审。下列是建议约定；若产品采用这些规则，研发可据此映射现有账号、文章与收藏能力。没有宣称现有接口已经存在。

## 对象与路径

对象为当前用户、文章及两者的收藏关系。建议业务唯一范围为当前用户 + 文章稳定 ID。

主路径：打开文章 → 读本人收藏状态 → 点击收藏 → 确认成功 → 按钮已收藏 → 本人收藏列表可见。

反向路径：点击取消 → 确认成功 → 按钮未收藏 → 本人收藏列表移除。取消收藏不删除文章。

## 组件与规则

- **R-001【建议】** 详情按钮由权威收藏状态派生：未收藏显示“收藏”，已收藏显示“已收藏”；状态未知时先加载，不能假定未收藏。
- **R-002【建议】** 点击时提交“目标状态为已收藏/未收藏”，不只发送“取反”。服务端按当前用户 + 文章保障同一目标操作可重试，不创建重复关系。
- **R-003【建议】** 提交中禁用重复点击；成功后更新本地显示并使个人列表失效，下一次进入时重新获取。失败保留原权威状态并提供重试，不先改变永久数据。
- **R-004【建议】** 收藏列表只包含本人有效收藏，建议按收藏时间倒序、文章稳定 ID 作为同时间的稳定次序；空列表显示“还没有收藏”，读取失败显示重试，不混为空态。
- **R-005【建议】** 所有读取/写入以登录身份为准，不信任请求体指定的任意用户 ID。未登录点击时进入既有登录流程，登录后返回原文章，是否自动续做需产品约定；本例建议返回后由用户再次确认操作。
- **R-006【建议】** 文章已删除或无权阅读时，不继续新增收藏；历史收藏可展示“内容不可用”及取消入口，不让旧链接打开其他文章。

## 逻辑数据契约

| 契约 | 请求语义 | 响应语义 |
| --- | --- | --- |
| D01 读取状态 | 当前登录上下文 + 文章引用 | 权威是否收藏、可操作性，或明确的无权限/资源失效 |
| D02 设置目标状态 | 文章引用 + 期望收藏状态 | 服务端确认后的关系状态；按业务唯一范围幂等 |
| D03 读取本人列表 | 当前登录上下文 + 稳定分页条件 | 本人有效收藏、文章可用性与下一页信息 |

## 验收

| 用例 | 规则 | 给定—当—则 |
| --- | --- | --- |
| AC-001 | R-001、R-002 | 给定未收藏；点击收藏并重试同一目标操作；最终只有一条有效关系，按钮显示已收藏 |
| AC-002 | R-002、R-003 | 给定已收藏；取消成功后进入本人列表；该收藏移除，文章本身仍存在 |
| AC-003 | R-003 | 给定提交明确失败；返回详情；仍显示原权威状态，允许重试 |
| AC-004 | R-004 | 给定列表读取失败；进入收藏页；显示失败/重试，不显示“还没有收藏” |
| AC-005 | R-005 | 给定用户 A；尝试读取或改写 B 的收藏；服务端拒绝，不泄露 B 的列表 |
| AC-006 | R-006 | 给定原文章已删除；打开旧收藏；显示内容不可用，可取消该关系，不跳到其他文章 |

这份小功能不需要完整跨系统状态图，也不需要为不存在的平台能力创建 P0。它仍说明了对象、作用域、正反流程、异步结果和验收。
