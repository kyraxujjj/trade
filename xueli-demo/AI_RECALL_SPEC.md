# 专项补弱与模型存储设计

## 8. AI 阶段复习 / 补弱 · 从历史短板到专项课程

已明确的新定义：分析孩子过去的学习表现，归纳具体能力短板，连接已有专项课程；学后用新任务验证改善。

### 用户需求

家长想知道孩子究竟卡在哪里、为什么需要学这门课、学完有没有改善；孩子需要学会解决一类问题的方法，并能在新内容中用出来。

例如，writing、swimming、sleeping 在不同课中反复出现词尾问题，应归纳为“-ing 词尾发音需要支持”，推荐语音技巧单元。

### 产品定位与设计思路

方案一解决本课即时错点：整组读完后集中带练。阶段补弱在跨课层面分析共同原因，形成“短板方向 → 课程单元 → 学习 → 应用验证 → 更新画像”的链路。

优先复用现有课程、视频、标准音和练习资源，推荐到具体单元；原错题作为诊断依据，验证任务采用同能力的新题或新情境。

### 何时进入，何时不进入

有未解决的重复短板，且完成2–4个 Lesson 或达到时间间隔后生成建议；记忆回访出现新问题，可转入分析，但单次遗忘先视为待确认线索。

高正确率且无明显薄弱点的孩子走记忆回访。新样本不足、录音质量差或识别不确定时，先补充证据，不直接贴能力标签；不固定安排周测。

### 一期与后续边界

已选课堂方案一。专项补弱本版细化产品规则和可操作 Demo，实际接入现有课程服务；不要求先建自由排课的 Planner，也不自动生成替代课程。

首次优先推荐1个短单元，另给1个后续方向；避免一次推六门课。资源映射、归因阈值、阶段触发和学习负担上限需教研与研发共同确认。

### 如何从学习表现得到具体短板

① 汇总跨课事实：独立首次作答、错误位置、AI 帮助方式、练后表现、延迟回访、已有专项课程进度；每条证据保留来源 Lesson、题目、时间和评测可靠性。

② 按知识点与细分技能聚合，先排除设备噪声、未学内容、任务过难、疲劳等影响；区分“不会发音 / 不理解词义 / 不懂结构 / 不会在情境里用”。

③ 用多次、跨课、独立表现支持短板判断。示例门槛：至少2课、3条有效独立证据；不足时只显示“待确认”，通过1–2个简短区分任务补充证据，仍不明确则继续观察。门槛为设计建议，待教研确认。

④ 输出能力方向、细分目标、证据、可信程度与优先级；只更新被测技能。示例：“语音技巧 / -ing 词尾 /ɪŋ/”，而非“英语不好”。漏读一次 is 可能是朗读或注意力问题，须结合选词、理解或新情境表达，才能归因到句型与语法。

### 六类专项课程：保留原有板块名称，细分能力可映射到课程单元

专项板块 | 可归纳的具体方向 | 所需证据与边界 | 课程匹配与学后验证

语音技巧 | 音素、词尾、重音、连读等具体发音方法 | 跨词、跨课独立朗读中的稳定问题；先排除收音与识别误差 | 对应语音单元与标准音；用未练过但已认识的词句朗读验证

口语交际 | 提出请求、问答接续、表达需要、情境应答 | 真实或模拟交际中的独立表达；跟读正确不代表会交际 | 请求 / 交流场景单元；更换人物、物品与情境后独立应答

词汇与语法 | 词义辨析、词形变化、单复数、词汇搭配 | 词级理解与运用证据；同一问题设一个主归因，避免与句型板块重复推课 | 词汇与词形单元；换词、换物品后的理解与运用任务

句型与语法 | 语序、句子结构、主谓搭配、be 动词与时态表达 | 句级理解、选词和独立表达共同支持；不能只凭一次朗读漏词诊断语法 | 具体结构单元；换主语、动作或语境验证，而非只背原句

阅读 | 定位信息、理解指代、事件顺序、阅读推断 | 必须有实际阅读理解记录；没有阅读样本就标记“暂无依据” | 对应阅读策略单元；用新的适龄短文与问题验证

写作 | 拼写、句子完整、组织表达、标点与修改 | 依据适龄书面作答及评阅记录；读不准 writing 不能判断写作薄弱 | 对应书面表达单元；换话题独立写作，用同一量规比较

### 最大化利用现有课程资源

给课程和单元补齐可检索标签：板块、细分技能、知识点、年龄 / 水平、前置能力、单元目标、资源类型、时长、审核版本、有效状态、访问权限、标准音与配套验证任务。

匹配顺序：细分技能一致 → 年龄与难度适配 → 前置能力满足 → 资源已审核且可访问 → 结合已有进度去重。语义检索可召回候选，正式课程 ID 与教研标签负责校验；AI 解释推荐理由，不能编造课程链接。

学过一半：续学对应单元；已完成但未验证：直接验证；已通过且近期稳定：不重复推同单元。没有匹配内容或无访问权限：明确“暂未匹配”，保留需求，回原课程或转教研补标，不跳到无关课程。

课程详情显示“为什么推荐、要学会什么、预计时长、现有进度、学习入口”。启动正式课程时携带 child_id、course_id、unit_id、resource_version、skill_id、recommendation_id、resume_position、return_route，由课程服务鉴权并返回学习进度；现有课程播放页负责学习，返回补弱页时读取实际完成状态。

新的独立验证只说明本次相关技能的表现；与之后的跨课表现、延迟回访共同支持稳定性判断。知识技能证据和课程完成记录分别保存。

### 学习报告要回答的四个问题

这次解决什么能力问题；学了哪个专项单元与方法；新任务中能独立完成什么；哪些仍需帮助、下一步学什么。学习完成、帮助后完成、独立验证、长期保持分别呈现，不能合成一个“已掌握”。

示例：“这次学了 -ing 词尾的发音方法。原来不同课的词尾容易漏读；学后能独立读出 jumping、playing。先继续原课程，后续遇到同类词再观察。am / is / are 的选择仍待下一次专项学习。”

## 9. Learner Model 与 Learning Memory：记忆存在哪里

沿用原架构名称：Learner Model 是学习者当前状态，Learning Memory 是可追溯的学习事实与经历。以下为建议的后台设计，具体数据库由研发确认。

### Learner Model · 当前状态与判断

“这个孩子在什么技能上需要支持、判断依据有多充分、下一步推荐什么”。它是根据事实更新的结构化画像与状态，不是另一个保存聊天的语言模型。

持久化存后台业务数据库的学习者模型表：learner_skill_state、learner_profile。以租户 / child_id / skill_id 区分数据，保存当前状态、证据量、覆盖课数、更新时间、判断规则版本、证据引用与待验证标记。

### Learning Memory · 事实与学习经历

“孩子何时做了什么、独立表现如何、AI 如何帮助、帮助后怎样、专项课程学到哪里、隔几天是否还记得”。保留事件与前后结果，不用最新判断覆盖过去事实。

持久化存同一后台数据库中的事件与记录表：learning_event、intervention_record、memory_check；课程进度以现有课程服务为事实源，通过 course_progress_ref 关联。

数据 | 建议存储位置 | 关键内容 / 读写规则

学习者画像与技能状态 | 业务数据库；PostgreSQL / MySQL 等关系型数据库均可 | child_id + skill_id：状态、样本数、跨课数、独立 / 帮助后表现、证据引用、版本、updated_at。由评估服务更新，LLM 输出须经规则校验，不能直接任意覆盖。

原始学习事实与帮助记录 | 业务数据库的事件 / 记忆表；大规模后再按时间归档 | event_id、lesson / item / skill ID、first_result、hint_used、retry_result、assessment_quality、occurred_at。使用事件 ID 幂等写入，保留历史，不重复计数。

专项课程进度与验证 | 进度：现有课程服务数据库；推荐与验证：业务数据库 | recommendation_id 关联 course / unit / resource_version / skill 与进度引用；course_completed 与 independent_verification 分开存储，先写结果事件，再更新技能状态。

录音、视频、作业图片 | 现有对象存储 / 媒体服务 | 数据库保存资源 ID、对象键、评测引用与授权信息；不把大文件放入 Prompt 或画像表。按机构规则设置访问权限与保留期限。

当前会话与临时上下文 | 服务端会话 / Redis 等缓存；需要追溯的关键事件另写数据库 | 当前 Lesson、页面位置、短期对话与本次操作状态；有过期时间。缓存失效后从持久化记录恢复，不作为唯一的长期记忆。

课程资源与知识检索索引 | 现有课程库 / 内容库；必要时附向量索引 | 课程内容、教研标签和审核资源用于匹配；孩子的长期状态仍以业务数据库为准。若检索个人历史摘要，必须按 child_id / 租户过滤并回链原始事件。

### 一次专项补弱如何读写

进入阶段模块：读取最近2–4课及相关历史事件、最新技能状态、既有课程进度 → 生成带证据引用的短板方向与课程推荐 → 学习时由课程服务记录真实进度 → 收到幂等完成回调，只标记“学完待验证” → 新任务作答写入独立验证事件 → 评估服务更新相应 skill 状态与推荐结果。

同一孩子换设备仍从后台恢复；兄弟姐妹即使共用家长账号，也按 child_id 隔离。读取 Prompt 时只选当前任务需要的事实、最近状态和来源引用；长期记忆不依赖对话窗口长度，也不写进模型参数。

Demo 与正式系统：这个 HTML 只用浏览器 localStorage 保存示例进度，不上传孩子数据，不代表线上数据库已实现。正式版本必须走后台存储与课程服务；模型权重如需管理，由模型服务 / 模型仓库保存，与个人学习记忆分开。
